# 小笛车控助手 · 更新记录

## 2026-10-18 新增需求与修正（开发中）
- 安全修正：空调设备裸 on 改为请求 OPENAIR（使用保存的温度与时长），不再解锁车门。
- 车辆状态显示组件：云端有值则展示，其他如 EV/HEV 里程、健康状态字段缺失时显示“未提供”；新增手动刷新接入代码。
- 蓝牙自动解锁/上锁的独立开关及漏锁提醒需求已加入研发设计；新增蓝牙精确设备匹配、开关默认关闭、重复事件限流和不确定锁状态提醒的决策模型、单元测试。
- Android 蓝牙后台服务、设备选择、权限、真实车锁状态检测、通知振动尚未实现，不能视为已可使用。
- 空调型设备相同 off 帧难以区分“仅关闭空调”和“锁车并关闭空调”，需进一步确认指令约定。
- 本版尚无已验证可覆盖安装的 APK。

## V4.0.0-dev — 2026-10-17（开发中，未发布正式 APK）
- **新增：空调运行时间可在 APP 修改并持久化保存**（10/15/20/25/30 分钟，默认30分钟）。手机本地保存至 `xiaodi_climate/duration_minutes`；按钮和巴法云 MQTT 语音控制共用，`OPENAIR.timeSpan` 动态映射为 1–5。
- APP“设置 → 关于”新增“软件更新记录”按钮，直接展示 APK 随包内置的更新记录，并保留原作者鸣谢。
- 新增 `ClimateControlParamsTest` 验证时长编码/温度边界；Android GitHub Actions 工作流构建验证尚未确认。

- 实测巴法云空调 payload：`on#1#26#0#0#0`，实现六段协议的动态温度解析（15–31℃）；其它未知帧拒绝执行。
- `OPENAIR` 由用户口令携带的温度设定，`timeSpan=5` 固定运行 **30 分钟**；适用于每个合法的动态温度值。
- App 车辆页新增温度减/加、设定温度并运行30分钟、关闭空调（`CLOSEAIR`）按钮。
- 新增 `patch_dynamic_upstream.py`（替代初始固定 26℃ 补丁），包含 MQTT 命令门禁、协议转发、界面代码改动。
- 新增 GitHub Actions V4.0 专用构建和单元测试；仅上传实验 APK Artifact，**不作为可覆盖原版安装的正式更新包**。
- 尚未执行成功的构建/真车实验、原 APK 签名一致性验证；所有源码状态仍为实验性。
- 新增上游项目与作者署名：fm1223/byd-android，jkaberg/pyBYD（仅功能调研）。
- 设计米家/巴法云空调类设备联动：“打开小迪”“关闭小迪”“小迪空调26度运行30分钟”。
- 新增 MQTT 命令解析雏形，拒绝未知消息，避免误触发。
- 明确真正启动/熄火整车与空调控制的技术边界。
- 覆盖安装要求：包名、签名一致，versionCode 递增。原版 APK 的签名未核对。
- 已调研并写入实验性 `OPENAIR` 参数映射：26℃ -> 内部温度编码 12、30 分钟 -> `timeSpan=5`；参考 pyBYD 及 Overdrive-release。\n- 新增 `patch_upstream.py` 开发补丁：保留原包名与 `OPENDOOR` 解锁行为；MQTT `off` 先锁车，确认成功再 `CLOSEAIR`；调温帧暂只接收 26℃，执行 `OPENAIR`。\n- 尚未完成：实测巴法消息、国内版车型执行结果、APK 构建、签名与可覆盖升级验证。
